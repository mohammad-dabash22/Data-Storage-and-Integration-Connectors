# Discussion: Integration Connectors
## 1. What is the difference between Source and Sink connectors?
The primary difference between source and sink connectors lies in the direction of data flow relative to the messaging broker (such as Google Cloud Pub/Sub). A **Source Connector** functions as a data ingestor and producer; it monitors and extracts data from an external system (such as an operational database, SaaS application, or file store) and automatically publishes those changes as events into the messaging queue. In contrast, a **Sink Connector** functions as a consumer and loader; it subscribes to incoming messages from the messaging topic and automatically translates and writes that data into a target storage or analytics system (such as MySQL, Redis, or BigQuery) without requiring manual boilerplate ingestion code.
## 2. What are the applications of connectors?
Connectors are fundamental to event-driven architectures and distributed cloud systems because they enable reliable, code-free data integration between heterogeneous services. Common applications include **Change Data Capture (CDC)** and database replication (streaming database transaction logs to read replicas or search engines like Elasticsearch), **real-time analytics and ETL pipelines** (ingesting high-velocity IoT telemetry or clickstream events into data warehouses), **cache hydration** (automatically streaming operational updates into fast in-memory caches like Redis to reduce primary database loads), and **enterprise application integration** (synchronizing events seamlessly between third-party SaaS platforms like Salesforce and internal cloud backends).
